# Dog Years — Claude Code project guide

Dog Years is a mobile habit app where a virtual dog reacts to the user's real behavior.
The dog brings the leash when the user has barely moved, play-bows after long sitting,
drops a ball by the phone after an hour of social media, yawns before bedtime, and rests
its head on the user after a low mood check-in. The user takes care of the dog by taking
care of themselves.

Launch market: the Philippines first (about 88% Android), then the US. Android and iOS
are equally important.

## Stack (summary)

- React Native + Expo (SDK 57 as of M0), TypeScript strict, Expo Router, Expo dev client
  (NOT Expo Go: native modules are required), EAS Build.
- iOS Screen Time: `react-native-device-activity` (config plugin generates extensions).
- Android app usage: local Expo module in Kotlin (`modules/android-usage-stats`).
- Steps: HealthKit (iOS); Health Connect + Recording API fallback (Android).
- Dog animation: Rive (`@rive-app/react-native`) behind a `DogRenderer` adapter, with a
  placeholder renderer until the real `.riv` file exists.
- Local data: `expo-sqlite` + Drizzle ORM. On-device first.
- Backend (later milestone): Supabase (auth, Postgres, RLS). Daily aggregates only.
- Payments: RevenueCat. Notifications: `expo-notifications` (local first).
- State: Zustand. Tests: Jest + React Native Testing Library.

## Commands

```bash
npm install
npx expo start --dev-client      # run JS against an installed dev build
npx expo run:ios                 # local native build (needs Xcode)
npx expo run:android             # local native build (needs Android Studio)
npm test                         # Jest (engine tests must always pass)
npm run typecheck                # tsc --noEmit
npm run lint
npm run simulate -- --persona=desk-worker   # simulated dog day; --persona=all, --days=N, --all
npm run test:coverage            # engine coverage threshold is enforced (CI runs this)
npx drizzle-kit generate         # after editing src/data/schema.ts: writes a new migration
eas build --profile development --platform all
```

## Non-negotiable product rules

1. **The dog never suffers.** No crying, injury, sickness, hunger damage, weight loss,
   running away or death. Low states are only: bored, sleepy, restless, asking.
2. **No guilt copy.** The dog invites ("Biscuit brought you the leash"), it never blames
   ("Biscuit is sad because of you"). Every user-facing string lives in `src/copy/` and must
   pass the copy rules in `docs/PRD.md`.
3. **Progress never resets to zero.** No consecutive-day streak counters. Count totals and
   "good days". Growth and bond only go up.
4. **Nudge budget.** At most 3 push notifications per day (user can lower it), at least
   2 hours apart, never in quiet hours or after bedtime.
5. **Money never replaces the habit.** Nothing purchasable improves the dog's mood, skips a
   walk or repairs progress. Paid items are cosmetics and premium features only.
6. **No food judgment.** Meal logging (later) is about regular meals only. Never calories,
   weight, BMI or "good/bad food".

## Non-negotiable engineering rules

1. **The dog engine is pure.** `src/engine/` must not import React, React Native, Expo,
   SQLite or call `Date.now()` / `new Date()` without an argument. Time and data are passed
   in. Every rule has unit tests. See `docs/DOG_ENGINE.md`.
2. **Recompute on open.** Background wake-ups are unreliable on both platforms. Background
   code (Screen Time extension, HealthKit observer, Android WorkManager) only records events
   and schedules local notifications. The UI always recomputes dog state from stored data
   when the app comes to the foreground.
3. **Privacy by default.** Never send app names, app tokens, package names, raw step
   samples, location or mood notes to any server or analytics tool. Sync only daily
   aggregates defined in `docs/ARCHITECTURE.md`.
4. **Continuous Native Generation.** Do not hand-edit `ios/` or `android/`. They are
   generated by `npx expo prebuild`. Change native config through `app.config.ts` and config
   plugins. Native code lives in `modules/` (Expo modules) or library plugins.
5. **Platform services behind interfaces.** Every platform service (`HealthService`,
   `ScreenTimeService`, `NotificationService`, `PurchaseService`) has an interface, a real
   implementation per platform, and a mock used in tests and simulators.
6. **Dependencies.** Install with `npx expo install <pkg>` so versions match the Expo SDK.
   Pin Rive versions exactly (a known Android performance regression exists between runtime
   versions). Before adding any new dependency, check it supports the current Expo SDK and
   the New Architecture.
7. **Don't guess platform behavior.** For HealthKit, Screen Time, Health Connect, usage
   stats and Rive, check the official docs or the library README before writing code. If
   behavior differs from these docs, update the docs and note it in the task.
8. **Real devices.** Screen Time, HealthKit, Health Connect and usage stats do not work
   fully in simulators/emulators. Use the mock services in simulators and tell the human
   which steps need a physical device.

## Session workflow

- After each major change update `PROGRESS.md` (status, next steps) and tick
  `docs/MILESTONES.md`. Update this file only for lasting conventions or commands.
- Engine decisions not in the spec go in `docs/DOG_ENGINE.md` §13.
- `dog-years-blueprint/` is the original blueprint, kept for reference; `docs/` is live.

## Code style

- TypeScript strict, no `any`. Prefer small pure functions.
- Feature folders under `src/features/`. Shared UI under `src/components/`.
- Dates: store UTC ISO strings; convert with the user's IANA timezone (default
  `Asia/Manila`). Day boundaries follow the user's timezone, not UTC.
- Accessibility: every dog state has a text description for screen readers; respect the
  OS "reduce motion" setting.
- Strings: English in `src/copy/en.ts`. Filipino (`fil.ts`) will be written by a native
  speaker; do not machine-translate.

## Things only the human can do

Claude Code cannot do these; when a task depends on one, stop and ask the human:
Apple Developer account, bundle IDs, App Group, Family Controls (Distribution) entitlement
requests, Google Play Console setup and declarations, RevenueCat dashboard setup, Supabase
project creation and keys, the Rive `.riv` file from the animator, store listings, and any
testing on physical devices.
